# mania-skills

참고 : AI Slop 프로그램입니다.

osu!mania 4K 스킬셋 분석기. osu! 공식 서버, mamesosu, 그리고 이 PC의 `scores.db` 세 곳에
흩어진 기록을 하나로 합쳐서 스킬셋별 레이팅과 단위인정(dan)을 계산하고, 약한 스킬셋을
겨냥한 맵을 추천합니다.

두 서버 어느 쪽도 상대방 플레이를 모르기 때문에 "합친 진짜 실력"이 나오지 않는 것을
해결하려고 만들었습니다.

## 무엇을 하는가

**세 소스를 동시에 수집합니다.** 온라인 두 곳은 top play만 주지만, 단위인정은 무덤·러브드
채보 클리어로 갈립니다. 그래서 로컬 `scores.db` 로 대부분의 기록을 가져올 수 있습니다

**MSD를 로컬에서 계산합니다.** 번들된 MinaCalc CLI(`vendor/msd.exe`)로 채보마다 8개
스킬셋 값을 뽑고, Etterna의 AggregateSSRs 방식으로 플레이어 레이팅을 만듭니다
(mania-tracker 공표값을 rmse 0.24로 재현).

**단(dan)을 로컬에서 재현합니다.** mania-tracker의 `dan-evidence`를 역설계해서 구현했기
때문에, 그쪽이 볼 수 없는 mamesosu·로컬 클리어도 같은 기준으로 채점됩니다.

**정확도를 두 체계로 보여줍니다.** osu!mania는 판정을 여섯 칸으로 나눠 가중치를 주고,
Etterna의 wife3는 ms 단위 오차를 연속 곡선으로 채점하며 미스를 −2.75노트로 칩니다. 같은
93%가 아닙니다. 판정 개수에서 타이밍 편차를 역추정해 임의의 OD·판정 난이도로 환산합니다.

**맵을 추천합니다.** 그냥 맵만 추천합니다

## 어떻게 측정하는가

### 1. 기록 수집

세 소스를 동시에 조회하고, 하나가 실패해도 나머지로 계속합니다.

| 소스 | 무엇을 주는가 |
|---|---|
| osu! 공식 (mania-tracker 프록시) | top play. pp 기반이라 랭크 채보만 |
| mamesosu (bancho.py v1) | 그 서버의 top play |
| 이 PC의 `scores.db` | **통과한 모든 플레이**. 무덤·러브드 포함 |

아이디는 숫자 id 든 닉네임이든 받습니다. `scores.db` 는 (채보 md5, 배속)당 정확도가 가장
높은 기록만 남깁니다. 설치되어 있지 않은 채보는 제외됩니다 — MSD 를 로컬에서 계산하려면
`.osu` 파일이 필요하기 때문입니다.

**채보의 신원은 md5 입니다.** BeatmapID 가 아닙니다. 레이트체인저 팩은 원본을 복사하면서
BeatmapID 를 그대로 들고 가기 때문에, 이 PC 만 해도 169 개의 id 를 469 개 파일이 공유하고
있고 그중 하나는 서로 무관한 66 개 채보가 나눠 씁니다. id 를 믿으면 `Sahara [_]` 를 친
기록에 `[Sahara 1.45x]` 의 난이도가 붙습니다 (실측 +8.5 MSD).

### 2. 채보 난이도 — MSD

번들된 MinaCalc(`vendor/msd.exe`)에 `.osu` 를 노트 행으로 변환해 넣고 8 개 스킬셋 값을
받습니다. 4K / 6K / 7K 만 지원합니다.

배속 모드가 걸린 기록은 노트 타임라인을 압축해 계산하거나, 가능하면 mania-tracker 의
rated 엔드포인트에서 받아옵니다. 그 엔드포인트는 MSD 와 단을 한 응답에 같이 주므로 단도
함께 캐시합니다.

### 3. 스킬셋 레이팅

MSD 는 **93 % 정확도에서의 난이도**로 정의된 값이라, 플레이의 정확도로 비례 조정합니다.

```
유효 SSR = MSD × (정확도 / 0.93)
레이팅   = 1.04 × Etterna AggregateSSRs(유효 SSR 목록)
```

**93 % 미만 기록은 레이팅에서 제외합니다.** 그 아래로는 위 식이 외삽이기 때문입니다 —
84 % 짜리도 채보 MSD 의 90 % 를 인정해 주는 탓에, 같은 채보를 15 %p 낮은 정확도로 친 1.5x
배속 기록이 모든 깨끗한 기록을 제치고 1 위에 올라와 있었습니다. mania-tracker 공표값과
대조한 결과 **93 % 까지는 오차가 전혀 변하지 않고**(최대 0.408) 94 % 에서 깨집니다(2.188).

합산 풀에서는 같은 채보를 두 번 세지 않도록 md5 기준으로 정확도가 높은 쪽만 남깁니다.

### 4. 단위인정

채보의 단은 mania-tracker 에서 받아옵니다 (MSD 의 함수가 아니라서 계산할 수 없습니다).
그 위의 모든 계산은 로컬에서 재현하므로, mania-tracker 가 볼 수 없는 mamesosu · 로컬
클리어도 같은 기준으로 채점됩니다.

1. 정확도 **92 %** 이상인 클리어만 셉니다
2. 정확도로 보정합니다 — **96 %** 가 기준선이고, 그 위는 가산 (100 % 에서 +1.50), 아래는 감산
3. MSD 프로필로 **jack / tech / speed / stamina** 네 버킷에 넣습니다 (최고 버킷과 0.076 이내면 두 곳에 중복 배정)
4. 버킷마다 **상위 20 개 중 하위 3 개를 버리고 나머지 17 개를 평균**
5. 네 버킷의 평균이 플레이어 단

단 조회는 요청 한 건이 채보 하나라, 로컬 기록이 많으면 1000 건이 넘습니다. 그래서 **어떤
버킷의 상위 20 위에도 들 수 없음이 증명되는 채보는 조회하지 않습니다.** MSD 로부터 단을
추정하는 직선(`0.5427 × 최고 스킬셋 − 3.64`)에 안전 마진 1.5 를 더한 상한이 그 버킷의
현재 하한보다 낮으면 그렇습니다. 실측 576 개 → 255 개, 추정치 차이 0.052 단.

### 5. 정확도 — 두 체계

osu!mania 와 Etterna 는 같은 것을 재지 않습니다.

| | osu!mania (ScoreV1) | Etterna wife3 |
|---|---|---|
| 방식 | 판정 여섯 칸의 가중 합 | ms 오차의 연속 곡선 |
| 320 과 300 | **같게** 셈 (둘 다 300) | 다르게 셈 |
| 미스 | 0 | **−2.75 노트** |
| 채보 OD | **영향 받음** | 무관 |

같은 플레이가 osu! 에서 100 % 인데 wife3 로는 96.5 % 일 수 있습니다 (전부 300 이고 320 이
하나도 없는 경우). 그리고 osu! 정확도는 **서로 다른 채보끼리 비교할 수 없습니다** — 판정 창이
OD 1 점당 3 ms 좁아지므로, 28 ms 편차의 같은 플레이가 OD 0 에서 99.22 %, OD 10 에서
91.98 % 로 읽힙니다.

기록에 남는 것은 판정 개수뿐이므로, **거기서 타이밍 편차를 역추정**합니다. 다섯 개 판정 칸의
관측값에 미지수 하나라 충분히 과결정된 적합이고, 창이 OD 를 따라 움직이므로 같은 실력이면
OD 와 무관하게 같은 값이 나옵니다. 창 안에서 균등분포를 가정하는 방식은 최대 8 %p 낮게
읽혀서 버렸습니다 — 실제 타격은 가운데로 몰립니다.

알려진 편차 8 ~ 36 ms, OD 0 ~ 10 구간의 모의 플레이로 검증: **편차는 0.1 ms, 정확도는
0.12 %p 이내**. 곡선 자체는 Etterna 공표 표와 23 ms 에서 99.112 % 로 일치합니다.

역추정한 편차가 있으면 **임의의 OD 와 판정 난이도(J1 ~ J8)로 다시 계산**할 수 있습니다.
환산은 기록된 값을 기준점으로 삼고 두 OD 의 차이만 모델링하므로, 채보의 실제 OD 를 고르면
기록값이 그대로 나옵니다(오차 0.000000 %p). 교차 환산 오차는 0.040 %p.

미스는 타이밍을 놓친 것인지 아예 안 누른 것인지 osu! 가 구분해 기록하지 않아 전부 −2.75 로
칩니다. 리플레이를 읽지 않는 한 방법이 없습니다.

### 6. 예상 정확도

플레이어 본인의 기록에서 **채보 난이도 → 타이밍 편차** 관계를 회귀합니다.

```
편차(ms) = a × MSD + b        (MSD 20 이상, 최소 20 개 기록)
```

편차가 나오면 판정 창을 거쳐 예상 정확도가 나옵니다. 새로고침할 때마다 다시 적합하므로
실력이 늘면 예측도 따라갑니다. 적합 범위 밖(±3 MSD) 채보에는 값을 내지 않습니다.

70/30 홀드아웃 20 회 반복 검증: 편차 평균절대오차 **3.5 ms**, 정확도 오차 **중앙 1.2 %p,
p90 4.1 %p**. 가늠용 추정치이지 인용할 숫자가 아닙니다.

### 7. 맵 추천

약한 스킬셋(또는 선택한 스킬셋)을 훈련시킬 채보를 mania-tracker 채보 인덱스에서 고릅니다.
인덱스는 응답을 48 개로 자르고 `page` 가 동작하지 않으므로, 단 구간을 0.25 폭으로 잘라
훑습니다.

**어디를 훑는가** — 단 추정치가 아니라 **예상 정확도**를 기준으로 잡습니다. 단 추정치는
최고 20 클리어의 평균, 즉 천장입니다. 이 PC 기준 실제 클리어의 중앙값은 단 10.8 인데
추정치는 12.8 이라, 추정치에 창을 걸면 여태 클리어한 것의 상위 15 % 안쪽만 나왔습니다.

세 구간으로 나눠 채웁니다.

| 구간 | 예상 정확도 | 개수 |
|---|---|---|
| 고점 다지기 | 90 – 93 % | 40 |
| 주력 | 95 – 97 % | 40 |
| 저점 다지기 | 98 – 100 % | 20 |

구간 사이를 띄운 것은 의도적입니다 — 각 그룹의 성격이 서로 섞이지 않습니다.

**무엇을 거르는가**

- 이미 친 채보
- 플레이 수 100 회 미만 — 3 회짜리 첫 업로드 부류가 여기서 빠지고, 페이지가 사라진 채보도 대부분 함께 걸러집니다
- 이름에 `vibro` 가 있는 채보 (jack 추천 시). 인덱스 자체의 `vibro` 플래그는 거의 아무 데도 안 붙어 있어서 이름이 더 정확합니다
- **단과 MSD 가 2.0 이상 어긋나는 채보** — 점프트릴·LN 팩은 델타급으로 깨기 어려운데 MinaCalc 는 MSD 21 로 보고, vibro·트롤잭은 반대로 MSD 만 부풉니다. 어느 쪽이든 MSD 기반 예측이 무의미하므로 잘못 정렬하느니 내놓지 않습니다. 2.0 은 그 추정 직선의 p95 잔차입니다

**무엇을 먼저 보여주는가** — 구간 안에서, 정크 여부 → **난이도명·태그에 그 기술이 적혀
있는지** → 집중도 순입니다. `chordjack`, `speedjack`, `minijack`, `longjack` 같은 단어를
인덱스에서 이름으로 직접 검색하는데, 분류기가 "jack" 으로 뭉뚱그리는 것보다 매퍼가 직접
써 놓은 이름이 더 강한 신호이기 때문입니다.

한 곡은 한 번만 나옵니다. 배속판·재업로드는 올린 사람이 달라도 같은 곡이라 제목만으로
중복을 제거합니다.

**집중도** 는 그 채보가 목표 기술에 얼마나 집중돼 있는지인데, 원값은 패턴마다 스케일이
다릅니다 — jack 채보는 0.15 ~ 0.35 로 퍼지지만 stream 은 jumpstream · stamina 와 본질적으로
같이 나오기 때문에 전부 0.01 ~ 0.09 에 뭉칩니다. 그래서 화면에는 **후보군 내 순위 백분율**로
표시합니다.

## 실행

```
python app.py
```

Python 3.12+ 와 `requests`, `pillow`(아이콘 생성용)가 필요합니다. Windows 전용이고,
`scores.db` 파싱과 번들 바이너리가 stable 클라이언트를 전제로 합니다.

배포용 단일 실행 파일:

```
python scripts/release.py
```

빌드하고, 빌드한 기계의 개인 데이터가 산출물에 섞이지 않았는지 검사하고, 빈 캐시로 한 번
실행해 첫 실행 화면이 실제로 비어 있는지 확인한 뒤 zip으로 묶습니다.

각 모듈 상단 주석에 "왜 이렇게 되어 있는지"를 적어뒀습니다. 상당수가 측정해서 알아낸
것이라 숫자가 함께 있습니다.

## 개인정보

앱이 학습한 것(osu!/mamesosu id, 플레이 기록, 비트맵 폴더 색인)은 전부 소스 트리 밖
`%LOCALAPPDATA%\mania-skills\cache`에 저장됩니다. 배포물이 정의상 파일 하나가 되도록
하기 위해서고, 그래서 exe를 남에게 건네도 캐시가 따라가지 않습니다.

`scripts/release.py`가 빌드마다 이를 검사합니다.
실행 파일과 그 안에 압축된 모든 엔트리를
풀어서 빌드 기계의 id·경로·`scores.db`의 플레이어 이름을 문자열로 찾고, 하나라도 나오면
빌드를 중단합니다.

## 알려진 것

- 백신이 오탐할 수 있습니다. 서명 없는 PyInstaller 단일 파일은 실행할 때마다 자신을
  `%TEMP%`에 풀고 번들 바이너리를 창 없이 실행하는데, 이는 드로퍼의 행동 프로필과
  통계적으로 닮았습니다. Microsoft에는 오탐 신고가 접수되어 정상 판정을 받았습니다.
- `vendor/msd.exe`는 MinaCalc CLI 빌드로, 이 저장소의 코드가 아닙니다.
- osu!lazer는 지원하지 않습니다. 스코어를 realm 데이터베이스에 두는데 읽을 수 없습니다.
